# v3.148.0 _2026-11-??_

## Testing

- [#6443](https://github.com/Dart-Code/Dart-Code/issues/6443)/[#6445](https://github.com/Dart-Code/Dart-Code/issues/6445): Synthetic test nodes like `setUpAll` and `tearDownAll` no longer contribute towards the shown test counts.
- [#6437](https://github.com/Dart-Code/Dart-Code/issues/6437)/[#6442](https://github.com/Dart-Code/Dart-Code/issues/6442): Errors during test loading (before `setUp()`) are now correctly shown in the Test Results panel.
- [#6400](https://github.com/Dart-Code/Dart-Code/issues/6400)/[#6404](https://github.com/Dart-Code/Dart-Code/issues/6404): Test nodes are no longer incorrectly removed from Test Explorer if the test file is edited during a test run.
- [#6387](https://github.com/Dart-Code/Dart-Code/issues/6387)/[#6388](https://github.com/Dart-Code/Dart-Code/issues/6388): [@NemesisDevX](https://github.com/NemesisDevX) contributed a fix for incorrect test nodes being reused and updated during a test run.
- [#6386](https://github.com/Dart-Code/Dart-Code/issues/6386)/[#6422](https://github.com/Dart-Code/Dart-Code/issues/6422): [@NemesisDevX](https://github.com/NemesisDevX) contributed a fix to prevent phantom test nodes for test helper functions from appearing in Test Explorer.
- [#3910](https://github.com/Dart-Code/Dart-Code/issues/3910)/[#6426](https://github.com/Dart-Code/Dart-Code/issues/6426): Phantom test nodes from inside parameterized/dynamic test/group calls no longer appear in Test Explorer. Only concrete nodes from running the tests appear.

## Commands

- [#6369](https://github.com/Dart-Code/Dart-Code/issues/6369): Creating new projects no longer sometimes triggers an additional `pub get` due to a race with file watchers.
- [#6299](https://github.com/Dart-Code/Dart-Code/issues/6299)/[#6301](https://github.com/Dart-Code/Dart-Code/issues/6301): [@NemesisDevX](https://github.com/NemesisDevX) contributed a fix for workspaces inside a dot-folder (for example inside a `.gemini/antigravity-cli/worktrees` folder).
- [#5285](https://github.com/Dart-Code/Dart-Code/issues/5285)/[#6410](https://github.com/Dart-Code/Dart-Code/issues/6410): Manually restarting the analysis server while it's starting up will no longer show a "Connection to server got closed" error.
- [#6432](https://github.com/Dart-Code/Dart-Code/issues/6432)/[#6433](https://github.com/Dart-Code/Dart-Code/issues/6433): The "Copy SDK path to Clipboard" buttons are now "Copy SDK bin path to Clipboard" and consistently copy the path with `/bin` regardless of which notification they were shown on.
- [#6413](https://github.com/Dart-Code/Dart-Code/issues/6413): The **Dart: Toggle Show TODOs** command no longer appears in the command palette when not in a Dart project, and the **Dart: Open on pub.dev** command no longer appear in the command palette at all (as it is a context menu command).
- [#6378](https://github.com/Dart-Code/Dart-Code/issues/6378)/[#6396](https://github.com/Dart-Code/Dart-Code/issues/6396): When the `dart.enablePub` setting is `false`, several Pub commands that were still showing up in the UI are now hidden.

## Editor

- [#6390](https://github.com/Dart-Code/Dart-Code/issues/6390)/[#6399](https://github.com/Dart-Code/Dart-Code/issues/6399): Extension restarts due to modifying settings are now debounced to reduce the chance of applying invalid values when manually editing `settings.json` if auto-save is enabled.
- [#6277](https://github.com/Dart-Code/Dart-Code/issues/6277)/[#6335](https://github.com/Dart-Code/Dart-Code/issues/6335): If the analysis server crashes and is automatically restarted, it now correctly reconnects to DTD to support functionality like the Property Editor and Widget Preview.
- [#6251](https://github.com/Dart-Code/Dart-Code/issues/6251)/[#6340](https://github.com/Dart-Code/Dart-Code/issues/6340): The "Analysis Server has Terminated" prompt no longer provides a button to restart if it was a crash that restarted the server automatically.
- [#5826](https://github.com/Dart-Code/Dart-Code/issues/5826)/[#6410](https://github.com/Dart-Code/Dart-Code/issues/6410): The "command 'dart.edit.codeAction.apply' already exists" error no longer appears sometimes when restarting the analysis server while it was in an initializing state.
- [#6454](https://github.com/Dart-Code/Dart-Code/issues/6454): Many improvements have been made to extension startup performance with the goal of having the analysis server up and responsive as quickly as possible. Some of this work is still in progress.

## Flutter

- [#6381](https://github.com/Dart-Code/Dart-Code/issues/6381)/[#6409](https://github.com/Dart-Code/Dart-Code/issues/6409): When capturing logs, Flutter log files no longer show in the picker in Dart-only workspaces.
- [#6380](https://github.com/Dart-Code/Dart-Code/issues/6380)/[#6408](https://github.com/Dart-Code/Dart-Code/issues/6408): Flutter tasks no longer show in the tasks list in Dart-only workspaces.
- [#6376](https://github.com/Dart-Code/Dart-Code/issues/6376)/[#6414](https://github.com/Dart-Code/Dart-Code/issues/6414): The **Flutter: Inspect Widget** commands now only show when an active debug session is a Flutter session and has widget inspector support.
- [#6487](https://github.com/Dart-Code/Dart-Code/issues/6487): Handling of an unresponsive Flutter device daemon (which may be caused by an old version of MSYS2 `git`) has been improved.
- [#4840](https://github.com/Dart-Code/Dart-Code/issues/4840): An issue with selecting devices or starting debugging Flutter apps with certain builds of `git` on `PATH` (MSYS2, devkitPro) was resolved upstream. If you use msys2/devkitpro and have their versions of `git` on `PATH`, upgrade to their latest versions to avoid this issue.

## Misc

- [#6351](https://github.com/Dart-Code/Dart-Code/issues/6351)/[#6367](https://github.com/Dart-Code/Dart-Code/issues/6367)/[#6347](https://github.com/Dart-Code/Dart-Code/issues/6347)/[#6349](https://github.com/Dart-Code/Dart-Code/issues/6349): [@NemesisDevX](https://github.com/NemesisDevX) contributed fixes for some errors during DTD shutdown.
- [#6423](https://github.com/Dart-Code/Dart-Code/issues/6423): The `dart.offline` and `dart.hotReloadOnSave` settings have been moved from the Flutter section to "Pub" and "Run & Debug" respectively.
- [#6431](https://github.com/Dart-Code/Dart-Code/issues/6431): Document position tracking (used to track locations of things like tests as you modify files) no longer fails for positions at line 1, col 1.
- [#5742](https://github.com/Dart-Code/Dart-Code/issues/5742)/[#6331](https://github.com/Dart-Code/Dart-Code/issues/6331): Some extension state (such as "Do Not Show Again", release notes, and survey prompt flags) is now stored globally so prompts are not repeated across different VS Code profiles.

## Release Process

- [#6136](https://github.com/Dart-Code/Dart-Code/issues/6136): Creation of VSIX files, Git tags, and GitHub releases has now been automated. All extension packages are built on GitHub Actions runners.
- [#6375](https://github.com/Dart-Code/Dart-Code/issues/6375)/[#6393](https://github.com/Dart-Code/Dart-Code/issues/6393)/[#6368](https://github.com/Dart-Code/Dart-Code/issues/6368)/[#6152](https://github.com/Dart-Code/Dart-Code/issues/6152): Extensions are now published to the VS Code and Open VSX marketplaces using trusted publishing from GitHub Actions.

## Features/Fixes Enabled with Future SDKs

The following items depend on changes to the Dart/Flutter SDKs that have not yet been released to stable channels. They may be available to test in the current beta/master channels and will show up in future SDK releases.

- [#5829](https://github.com/Dart-Code/Dart-Code/issues/5829): Isolates created at the start of a Flutter app are no longer sometimes left paused during startup/hot restart.
- [#4009](https://github.com/Dart-Code/Dart-Code/issues/4009): The analysis server now includes a quick-fix for the `sort_pub_dependencies` lint.
